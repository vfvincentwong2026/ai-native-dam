# Quick Start

## 1. Boot the local stack

```bash
git clone https://github.com/vfvincentwong2026/ai-native-dam.git
cd ai-native-dam
cp .env.example .env
docker compose up -d
```

Postgres: `localhost:5432` · MinIO S3: `localhost:9000` · MinIO Console: `localhost:9001`

## 2. Apply migrations

```bash
docker compose exec -T postgres psql -U dam -d dam < infra/migrations/0001_init.sql
docker compose exec -T postgres psql -U dam -d dam < infra/seed/0001_channels.sql
```

## 3. Verify the public showcase MCP endpoint

```bash
curl -s https://ai-native-dam.pages.dev/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

## 4. Install and typecheck locally

```bash
corepack enable
pnpm install
pnpm typecheck
pnpm test
```

## 5. Smoke the Builder Runtime

The smoke drives the full ADR 0010 chain against a real PGlite governance
store — spec approval, blueprint planning, provenance `apply_skill`, the
verify gate, and gated registration — then asserts the registered system
carries a non-empty `blueprint_hash` + `verify_report_ref`:

```bash
pnpm build
pnpm smoke:builder                       # uses .review/pgdata
DAM_PG_DATA_DIR=/tmp/dam-smoke pnpm smoke:builder   # or a scratch store
```

No external services and no LLM: the gateway runs in-process with its own
tokens on a random port, and compilation uses a stub completer because the
verify gate is structural. The run is idempotent — repeat runs reuse the
draft/registered records and just re-verify the chain.

For a REAL compile, fill `MODEL_ROUTER_BASE_URL` / `MODEL_ROUTER_API_KEY`
into `.env` (any OpenAI-compatible endpoint — OpenRouter, DeepSeek, local
Ollama) and run `pnpm build:real`: the same chain, but every file is
generated by the configured models through the budget-guarded model router.

## 6. Next: full governance plane
