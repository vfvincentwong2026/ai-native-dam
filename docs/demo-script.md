# AI-Native DAM 演示剧本（给客户演示时照着走）

> 用途：销售/交付同学给客户做现场演示的标准剧本。
> 配套入口：在线演示沙箱 https://ai-native-dam.pages.dev/demo/ · 治理大屏 https://ai-native-dam.pages.dev/governance/
> 演示数据全部为虚构样本，不含任何真实客户信息。

## 角色设定

- **客户角色**：一家内容公司的运营负责人，手里有几千条素材的版权要管，靠 Excel 和人脑记到期日。
- **演示者**：你。全程只需要一个浏览器。

## 剧本主线

**背景**：客户的素材库每周都有版权悄悄到期，等发现时要么已经违约、要么紧急下架损失惨重。

| 步骤 | 演示者操作 | 系统行为 | 演示要点（说给客户听） |
|------|-----------|---------|----------------------|
| ① 提需求 | 打开 /demo/，点「版权到期预警」预设芯片 | 需求文案自动填入 | "不用写代码，说人话就行" |
| ② 审批规格 | 展示 Spec 卡片：4 个字段、权限、3 条工作流；点「批准」 | 规格书进入构建 | "您不点头，一行代码都不会生成 —— 这是人类门禁" |
| ③ 看流水线 | 六个阶段动画 + 滚动日志 | 蓝图编译 → 生成 → 安装 → 测试 → 13 项门禁 → 注册部署 | "日志里的每一行都来自真实运行记录，包括失败自动修复" |
| ④ 用上系统 | 点「系统已上线」，操作预警台：切换「重点预警/观察清单」筛选 | 表格按级别过滤，5 条样本数据 | "这就是交付物：一个正在运行的服务，有 API、有数据库" |
| ⑤ 查出身 | 点「在治理大屏找到它」跳到 /governance/ | 大屏显示真实系统的注册记录、蓝图哈希、部署实例、心跳 | "每个系统都能一键回溯到您当初批准的那份需求" |

## 客户常问的临场问题

- **"这数据是真的吗？"** —— 沙箱里是虚构样本；真实系统的数据在大屏上，可以现场打开对比。
- **"我们要自己买服务器吗？"** —— 不用。可以跑在您的电脑上，也可以部署到您的云账号，部署目标登记制。
- **"我们已经有系统了怎么办？"** —— 切到产品页「已有系统接入」一节：一个 manifest 文件 + 四件清单，不动您的代码。
- **"坏了谁修？"** —— 流水线自带修复环；上线后心跳异常大屏立即可见，版本可以一键回切。
