第一步：说人话，提需求

不需要写代码、不需要画原型。像跟同事说话一样描述你要什么 —— 流水线会把它落成一份结构化规格书给你审批。

第二步：审批规格书（人类门禁）

AI 把你的需求结构化成 System Spec —— 实体、字段、权限、工作流。你点头，流水线才会动工。这就是治理的起点：没有审批过的 Spec，就没有后面的任何代码。

Entity · license_alert（预警记录）
字段类型必填
idstring是
asset_idstring是
expires_atdatetime是
alert_levelstring是
权限：read · write（决定生成哪些 API 端点）
Workflows · 自动化工作流
每日扫描：到期前 30 天列入观察清单
到期前 7 天自动升级为重点预警
输出「待续约 / 待下架」两条处置队列
存储：sqlite · 本地优先，零外部依赖
真实环境里，这一步由持有 Edit 令牌的审批人通过 MCP 两段式闸门完成 —— 批准动作本身也留痕。

第三步：流水线开工（约 10 分钟，这里加速演示）

规格确定性编译成蓝图，模型分级生成代码，沙箱真实安装/构建/跑测试，13 项门禁全过才允许注册。
