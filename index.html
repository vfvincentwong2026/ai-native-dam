01

为什么需要治理平面

Without DAM让 AI 直接写系统

  • 提示词进、代码出 —— 中间没有任何可检查的产物
  • 模型幻觉依赖版本，安装即失败，没人知道为什么
  • 测试全绿，一部署发现表都没建 —— 门禁形同虚设
  • 三个月后没人说得清这个系统是哪份需求、哪个模型造的

With DAM治理先行，生成在后

  • Spec 必须人工审批通过，蓝图由规则确定性编译
  • 依赖集、服务端入口、建表语句全部由编译器确定生成
  • 可执行沙箱真实安装、构建、跑测试，失败自动修复重试
  • spec → blueprint hash → system → instance 全链路可查证
02

六步流水线：从需求到部署

Step 1 · Spec

规格审批

业务需求落成结构化 System Spec：实体、字段、权限、工作流。人工审批通过才进入下一步。

人类门禁
Step 2 · Blueprint

确定性编译

Spec 按固定规则编译成蓝图：技术栈、模块拆分、文件清单。无 LLM、无随机 —— 同 Spec 永远同哈希。

纯函数
Step 3 · Build

受控生成

蓝图携带提示词计划，C0–C3 分级路由到不同模型；服务端入口、契约、建表语句由编译器直出，不经 LLM。

预算熔断
Step 4 · Verify

门禁验证

13 项确定性检查 + 可执行沙箱：真实安装依赖、tsc 类型检查、跑测试。失败文件定点修复重试。

13 gates
Step 5 · Register

溯源注册

验证通过才允许注册。系统携带 spec id、blueprint hash、verify report 引用 —— 四级溯源链闭合。

verify-before-register
Step 6 · Deploy

受管部署

健康探针先活查再登记，target → instance → heartbeat 全程留痕，旧版本实例一键吊销完成切换。

拒绝幽灵部署
设计原则：LLM 只出现在"填充业务逻辑"这一个环节；凡是能确定性推导的 —— 依赖清单、tsconfig、 server 入口、数据库建表 —— 一律由编译器生成。模型的不确定性被压缩到最小面积。

04

你能得到什么

⛓

全链路可审计

每个线上系统都能回答：来自哪份需求、哪版蓝图、哪次验证、谁批准的。合规检查从"翻聊天记录"变成一次查询。

◎

模型可替换

模型分级路由 + 传输层抽象，OpenRouter / DeepSeek / 本地 Ollama 随时切换。供应商锁定不存在，成本自己说了算。

▣

失败可修复

沙箱真实跑 install/build/test，失败时从编译日志定位责任文件、带上下文定点重生成 —— 0.4.0 就是靠修复环自愈通过的。

◈

能力可沉淀

Skill 注册表 + 蒸馏队列：好用的生成模式回流入库，下一次编译直接复用。系统越用越聪明，而不是越用越乱。

05

如何使用：十分钟跑通全链路

# 1. 克隆并安装git clone https://github.com/vfvincentwong2026/ai-native-dam && cd ai-native-dam && pnpm install
# 2. 配置模型路由（OpenRouter 免费模型即可起步）cp .env.example .env # 填入 MODEL_ROUTER_BASE_URL / API_KEY
# 3. 启动治理网关pnpm --filter @ai-native-dam/mcp-gateway start
# 4. 跑一次真实构建：Spec 审批 → 编译 → 生成 → 沙箱验证 → 注册pnpm build:real
# 5. 启动生成的系统并登记部署node .dam-runs/<run-id>/src/server.ts && node scripts/deploy-local.mjs

详细架构决策见仓库 docs/adr； 治理大屏上的 Skill 注册表、Spec 审批视图、蒸馏队列都是实时数据，不是截图。

06

常见问题

这和直接用 Cursor / Copilot 写代码有什么区别？

那些工具优化的是"写"的效率，DAM 管的是"能不能上线"的治理：需求先审批、蓝图确定性编译、生成受预算约束、验证走可执行沙箱、注册强制溯源、部署活查登记。AI 写的每一行系统代码都在这条流水线里留痕。

必须用指定的大模型吗？

不需要。模型通过 C0–C3 分级路由接入，传输层是可插拔的 ModelTransport：OpenRouter、DeepSeek、本地 Ollama 都已验证。换模型只改环境变量，治理链路和蓝图哈希完全不受影响。

生成的系统质量怎么保证？

三层：① 确定性文件（server 入口、契约、建表、tsconfig）不经过 LLM；② 13 项门禁 + 沙箱真实 install/build/test；③ 失败文件定点修复环。验证不过就不允许注册，注册不了就不存在部署。

数据会离开我的环境吗？

治理数据存在本地 PGlite/SQLite，生成的系统默认 node:sqlite 零外部依赖。唯一出网的是 LLM 推理调用 —— 指向哪个端点由你配置，包括完全本地的 Ollama。

现在是什么成熟度？

Founding Beta：六步流水线已端到端跑通真实系统（版权到期预警台 0.4.0 → 0.5.x），部署链闭环。沙箱目前是本机无隔离运行（dev-only），Docker 隔离沙箱在 ADR 0010 路线图内。

怎么接入我自己的业务需求？

写一份 System Spec（实体 + 字段 + 权限 + 工作流，仓库有模板），提交审批，然后 pnpm build:real。流水线会带着你的 Spec 走完编译、生成、验证、注册全程。
